## Status and proof rules

EXACT means carried source semantics with passing behavioral proof. EQUIVALENT means the described observable behavior is proved through HQ's business-owned durable engine. PARTIAL means the broader reference row still has the stated gap. MISSING means no implementation. NOT IMPLEMENTED IN STARNET requires source-proven absence. A passing subset never erases a remaining gap. COMPLETE in the controlled-landing report means EXACT or EQUIVALENT, with proof. The original 55-row denominator is retained; outbound COMMS evidence is included in the existing Signal dish/web row.

Every StarNet source path below exists in the checked-out reference. Source was inspected, not executed or modified. HQ shorthand: runtime filenames resolve under `packages/runtime/src`; server/main/projection/model-profiles/channel-hosts/mcp-hosts/acp-controller under `apps/control-centre/src`; app.js/world.js/station-model.js/floor-editor.js under `apps/control-centre/public`.

Proof keys: **SA** = `packages/runtime/test/station-acceptance.test.ts` (named behavior substring after colon); **SP** = `packages/runtime/test/station-protocols.test.ts`; **RP** = `packages/runtime/test/reference-model-provider.test.ts`; **AP** = `apps/control-centre/test/server.test.ts`; **UI** = `apps/control-centre/test/{projection,station-model}.test.ts`; **SM** = `scripts/control-centre-smoke.mts`. Other test filenames resolve under `packages/runtime/test`. External boundaries use deterministic injected transports/providers. Files/code-worker tests execute actual local tools; SM uses installed Chrome and an actual temporary local HQ host with paid models/channels/connectors disabled. No live service/account acceptance is implied.

## Architectural drift risks and preserved safety

- CommandContext owns trusted actor provenance; producer remains hq.runtime. Station events contain changed kind/record ID, not a coupled domain snapshot. HTTP actor claims cannot become authority. Event additions are additive.
- Durable validation/save-before-publication, one store writer, exact captured consent, paid invocation reservation and unknown usage retention remain underneath these systems. Each admitted retry buys a separately reserved and invoiced generation; no adapter buys a hidden retry. No fake revenue.
- Bigint cents and nanodollars remain separate canonical units. Wire JSON retains integer strings. Carried chain float guards read canonical recorded expenses; they are not a second financial ledger. Each model generation still reserves its exact admitted ceiling; source whole-line guards do not imply whole-line pre-reservation.
- Capabilities, connector namespaces and workspace keys include business ownership. MCP readOnlyHint cannot authorize an external effect. Assigned-room and legacy-office scopes are accepted across restart; grants remain business-owned.
- Scheduled next-fire/daily slot and Night Shift leash persist before actual work. Host admission ticks serialize briefly by business; actual scheduled executions overlap and later ticks can admit unrelated work. Human input records presence; SSE heartbeats never fabricate it. Standing consent covers only exact private writes on a bound Night Shift job; an external operation still requests consent. Halt persists before cancellation and is rechecked before model/tool dispatch.
- Inbox durability precedes actual work and Slack ACK/Matrix batch cursor movement. Outbound intent precedes send. Crash after send can leave UNKNOWN; suppressing automatic retry deliberately avoids duplicate effects. Telegram and Matrix cursors now persist after durable intake; Matrix restart no longer discards unclaimed input. No exactly-once delivery claim.
- ACP controls existing scoped jobs, never a second runtime/store. Editor cwd is reference data, not a grant. Only once consent is offered. AP also launches the real stdio process through authenticated local HTTP and proves its prompt becomes actual owned work/output.
- Optional station/config extensions preserve the current state model, but accumulated transcripts/channel records/fire journals enlarge full-snapshot writes. Retention and migrations need deliberate boundaries. Source JavaScript modules are isolated behind typed HQ adapters; broader reuse must retain notices and never import host-wide authority.
- In-process run leases express execution ownership only. Canonical joins/crates and interrupted-line reconciliation preserve evidence without pretending a lost process closure can resume.
- An admitted job's policy cannot change. Configuration is refused while its agent has a running or approval-paused job; future UI should explain the frozen admitted policy separately from next-job configuration.
- Main production composition currently authorizes business-001 only; runtime tests exercise two isolated businesses. Do not claim a multi-business deployment/operator selector from those tests alone.

## Operator configuration for the implemented paths

Start the ordinary local host with npm run control-centre. Paid execution stays off unless HQ_ENABLE_MODEL_EXECUTION=1. Recruit/configure/desk/notebook/gear and saved graph editing do not require a paid provider call. File writes and code execution require captured exact approval; code uses Node permission isolation. Browser tools use installed Chrome with private agent profiles.

Remote profiles come from HQ_MODEL_PROFILES_PATH: an array with provider, model, format (chat/anthropic/gemini), endpoint, optional keyEnv and pricing. Pricing strings are exact tokensPerBlock, inputNanodollars, outputNanodollars, cachedInputNanodollars, optional cacheCreationInputNanodollars. Supply verified tariffs; there is no guessed remote pricing. Default Responses profile uses the existing host OPENAI_API_KEY path. Local Ollama uses OLLAMA_MODEL and optional OLLAMA_BASE_URL (default http://127.0.0.1:11434/v1); no remote key is sent. Select only a configured provider/model in Configure crew.

HTTP MCP uses HQ_ENABLE_CONNECTORS=1 and HQ_MCP_PROFILES_PATH: array records {id,url,tokenEnv?,enabled?,toolRoles?}. enabled:false offers a host-configured catalog entry without networking until INSTALL; installed intent survives restart. toolRoles explicitly classifies original published tool names as act/observe for separately consented SOP readback. This explicitly initializes configured hosts; place connector gear with its installed id to grant crew access. Channel transport requires both model execution and HQ_ENABLE_CHANNELS=1 plus HQ_CHANNEL_PROFILES_PATH: an object keyed by the UI channel binding id. Supported host fields are tokenEnv (Telegram/Discord/Matrix), botTokenEnv/appTokenEnv (Slack), accountEnv/endpoint (Signal), homeserver (Matrix), optional apiBase. All Env fields name host environment variables, never contain persisted secret values. UI binding supplies existing agent, explicit owner user and allowed chats. Enabling a binding alone does not mean connected. Signal requires an operator-running registered signal-cli REST daemon.

ACP editor edge: run node scripts/acp-serve.mts with HQ_ACP_AGENT_ID set to an existing owned agent, optional HQ_ACP_BUSINESS_ID and HQ_ACP_URL pointing at the running local host. Only JSON-RPC goes to stdout; it proxies the authenticated owner, never opens the state file or grants its requested cwd. Scheduled work/Night Shift use the same explicitly enabled host execution path, durable limits, selected profile and human posture.

REST keys: optional HQ_WEB_KEYS_PATH contains host-only {businessId,name,keyEnv,origins} profiles. origins must be exact public HTTPS origins; values resolve from the named host environment variable only for that business and approved target. No key values are saved in station profiles or approvals.

Host model profiles may supply fallbacks:[{provider,model}]. Every target must already be a distinct explicitly priced host profile. The frozen job budget covers primary UNKNOWN reservations plus every admitted fallback. No model text changes the payer or clears unknown spend.

External HTTP harness: set a strong HQ_V1_KEY (at least 16 characters), explicit comma-separated HQ_V1_AGENT_IDS and optional HQ_V1_MAX_CONCURRENT. It remains inert while paid execution is disabled. The bearer is fixed to the host business; client model aliases select only those already-owned agents and their existing priced profiles. `/v1/models`, `/v1/chat/completions`, `/v1/runs`, status/events/stop share real HQ jobs. Idempotency-Key is durable; incomplete/unknown billing never becomes a successful zero-cost completion. Headless tool consent is cancelled rather than granted.

Responses SSE mapping follows [official streaming guidance](https://developers.openai.com/api/docs/guides/streaming-responses): actual output_text deltas are transient; the terminal provider response alone supplies final output/usage. No live API calls were needed for these tests.

Host profiles default to two source-classified transient retries (configurable maxRetries 0..6). Each generation attempt is separately priced and budget-admitted; unresolved invoices never disappear. Existing admitted jobs retain their original frozen retry policy. `model.retry_scheduled.v1` records intent before the cancellation-aware wait, never an invented network completion.

HTTP connector catalog: host profiles may set enabled:false to offer a configured connection without initial contact. PLACE GEAR lists actual available host entries and INSTALL performs initialize/tools/list; its separate connector placement grants capabilities. Installed durable catalog intent reconnects on host restart. Browser input cannot supply endpoint or secret references.

Connector SOP predicates: optional host MCP profile toolRoles maps actual published names to act or observe. readOnlyHint never grants a role or bypasses consent. The kernel records exact-operation receipts; a captured connector_readback schedules a fresh normal tool operation, including approval/restart, rather than hidden network I/O. Earlier model-requested reads cannot substitute for host check intent. Unsafe connector regex predicates are rejected before job admission.
